# 09 — Build the next mission from the state, with its strategic briefing

Status: ✅ done

## What the tools apply

`veaf-tools campaign next <campaign folder>` creates the next mission's folder and applies the state to it: the coalition of every campaign airbase, dynamic slots on the bases each side owns, the warehouses (ticket 06), the campaign data table loaded before `veafCampaign.lua` (garrisons, losses, scenery, stocks), and the `CAMPAIGN` module in `mission.yaml`.
The result is a valid mission folder that builds on its own — Claude's design comes on top of it, never instead of it.

## What Claude adds

The mission itself, built the way `FEAT-OBJECTIVE-MISSION-PROMPT` builds one: objectives chosen from the strategic situation (a depot to destroy before the next push, a base to free with CTLD troops), packages, support, and the enemy's intent decided for this turn (ticket 08).

## The strategic briefing

The usual briefing plus a **strategic situation** section: front line and zones held, what changed in the last mission, the enemy's state (stocks, what it lost), the campaign objectives and how many missions remain.
Its factual part is generated by the tools from the state, in both locales; Claude writes the narrative part.

## MCP actions

Claude drives the loop through the MCP: `campaign_status` (read the state), `campaign_apply` (ticket 08), `campaign_next` (this ticket); each documented in the mission-maker action catalogue (lockstep rule).

## Done when

Tests cover the folder produced from a state (airbases, slots, warehouses, data table), the briefing section in both locales, and the three MCP actions; `pyproject` ratchets respected.
