# FIX-V5-NUDGE-FALSE-POSITIVE

Status: ✅ done

## Problem

After `convert-v5` promotes `src/mission/` to v6, the next `build` still emits the
deprecation nudge:

> N trigger(s) v5 hérité(s) migré(s) en mémoire. Lancez `convert-v5` pour promouvoir…

— even on a correctly promoted v6 mission. The reported count is **2**.

## Root cause

`clear_veaf_triggers` (`mission_builder_worker.py`) flags a dictionary entry as a
*legacy v5 trigger* by matching its **value** against a list of Lua conditions
(`migrate_from_v5` branch), without looking at the **key**. Two of those values —
`return VEAF_DYNAMIC_MISSIONPATH~=nil` / `==nil` — are **also regenerated by the v6
triggers themselves** (`update_dictionary_with_veaf_entries`, keys[4]/keys[5]): the
`VEAF_DYNAMIC_MISSIONPATH` global is unchanged between v5 and v6 (unlike
`VEAF_DYNAMIC_PATH`, which became `VEAF_DYNAMIC_SCRIPTSPATH`).

So once `src/mission/` is promoted, it carries those 2 conditions on the **v6** dict
keys `VEAF_DictKey_ActionText_12005/12006`, and every later build re-counts them as
"legacy v5" → permanent nudge (count = 2).

Verified by the real v5 mission (Caucasus): legacy triggers use keys
`DictKey_ActionText_106xx..109xx`, whereas v6 triggers use
`VEAF_DictKey_ActionText_12001..12006` (`_VEAF_TRIGGER_DICT_KEYS`). The reliable
v5/v6 discriminant is the **key**, not the value.

## Decision

In the legacy-v5 detection, ignore entries whose key is a known v6 trigger key
(`map_key in _VEAF_TRIGGER_DICT_KEYS`). A v6 trigger is never a legacy v5 one.

- Promoted v6 mission → MISSIONPATH conditions on keys 12005/12006 → excluded → count = 0,
  no nudge.
- True v5 mission → keys 108xx/109xx (≠ 12001-12006) → still detected → legitimate nudge.

## Out of scope

- Reworking the nudge message itself.
- The promotion mechanism (works correctly).
